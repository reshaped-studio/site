# Authoring public Design Plan examples

The shared `example.njk` template renders one page per record in `src/_data/designPlans.json`. The landing page uses the same records for its gallery. Wireframes are explicit public assets in `src/img/design-plans/`; private studio documents are not read by this site.

Each record contains its slug, project overview, included scope, exclusions, opportunity, success-evaluation approach, insights and decisions, object guides, relationships, flows, requirements, open questions, and validation activities. Each flow step references an SVG plus an accessible description, task, rationale, and annotation. The preview image is an existing flow screen.

To replace an illustrative example with an authorized real project, update the record and its referenced assets. Update the document status, review ownership, and individual insight labels to accurately describe the evidence. Do not present assumed observations as research findings or publish client material without permission. Keep the slug if the existing URL should remain stable.

Tabs enhance otherwise visible object-guide sections. Enlargement controls appear only when the native dialog API is available. Wireframes remain static illustrations and cannot transact or send messages.
